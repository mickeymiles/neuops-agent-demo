# NO-011 备件邮件询价数字员工 — 设计规格

> Document Version: V2.0（双邮件流模型）
> Date: 2026-08-28
> Component: emp-mail-inquiry + skill-proc-mail-inquiry
> Status: 生效（作为测试用例与实现的单一事实源）

## Purpose

面向现场工程师**仅通过邮件**发起备件询价采购，实现全流程邮件自动化的双邮件流闭环：

- **内部流（对内，工程师 ↔ 智能体 ↔ 审批人）**：工程师邮件发起询价 → 智能体在同一邮件会话提交审批 → 审批人回复该会话确认 → 工程师回复备件更换完成 → 内部流程结束。
- **外部流（对外，智能体 ↔ 供应商）**：智能体向供应商发询价 → 供应商邮件回复报价 → 选中供应商下达订货 → 供应商回快递单号；**未选中供应商在回复报价后即被截止**。

两条流相互关联（共享同一询价任务），但**线程独立**：内部流基于工程师询价邮件线程，外部流基于每封询价邮件线程。

## 角色与邮箱约定

| 角色 | 流入/流出 | 说明 |
|------|-----------|------|
| 工程师 | 内部流发起+确认 | 发询价邮件；回复审批线程确认；回复备件更换完成 |
| 审批人 | 内部流审批 | 白名单邮箱，回复审批邮件（确认 / 指定供应商 / 拒绝） |
| 智能体（emp-mail-inquiry） | 双流编排 | 自动收发，无需人工登录 |
| 供应商 | 外部流 | 收询价→回报价→收订货→回单号；未选中者回报价即截止 |

采购邮箱 = `proc_mail_username`（发件与收件同一邮箱）。

## 紧急程度与报价截止

- 工程师询价邮件的正文**必填「紧急程度」**字段（如 `紧急程度：5min` / `1min` / `1h` / `24h`）。
- 系统 MUST 解析紧急程度，并按 `报价截止时间 = 邮件头 Date 字段（发送方声明时间）+ 紧急时长` 计算**报价截止时间**。
- 紧急时长映射（默认）：`1min→60s`、`5min→300s`、`1h→3600s`、`24h→86400s`；支持解析 `min`/`h`/`小时`/`天` 等单位。
- 测试环境统一用 `5min`。

### Scenario: 紧急程度驱动截止
GIVEN 工程师询价邮件正文含「紧急程度：5min」，邮件头 Date 字段时间为 T
WHEN 系统建任务
THEN 报价截止时间 = T + 300 秒，非固定 12h/48h

## 双邮件流状态机

```
内部流：
R-INIT(收询价/校验) → R_APPROVAL(提交审批回复工程师会话) → R_CLOSED(审批人确认 / 工程师回备件更换完成)
外部流：
R_SEND(发询价给供应商) → R_QUOTE(等报价, 未选中者回报价即截止) → R_ORDER(选中供应商订货) → R_SHIP(供应商回单号) → R_DONE
```

两流共用一个 `spare_mail_task` 记录，字段用 `internal_status` / `external_status` 分别表达两条流进度。

## 邮件模板（严格按设计文档，对内/对外分离）

### 内部流（对内，回复工程师询价会话或工程师发入）

| 模板 | 用途 | 触发 |
|------|------|------|
| X-工程师发起询价 | 工程师→智能体，含紧急程度 | 发起 |
| 审批邮件（回复 X 会话） | 智能体→工程师会话，抄送审批人，列报价+最低价+审批建议 | 报价收齐/到期 |
| 备件更换完成确认 | 工程师→智能体，标识内部流结束 | 工程师回执 |

### 外部流（对外，智能体→供应商 / 供应商→智能体）

| 模板 | 用途 | 触发 |
|------|------|------|
| 询价邮件 | 智能体→每个供应商，不含收货地址 | 建任务后 |
| 供应商报价回复 | 供应商→智能体 | 收询价后 |
| 订货邮件 | 智能体→选中供应商，含收货地址/要求测试报告+快递单号 | 审批确认后 |
| 快递单号回执 | 供应商→智能体 | 发货后 |
| 未选中截止通知（可选） | 智能体→未选中供应商 | 审批定标后 |

模板正文/主题由 `spare_mail_config`（DB）维护，DB 优先，skill JSON 兜底。

## Requirement 清单

### R-FR-01 识别询价并建任务
系统 SHALL 识别收件箱中主题/正文含「询价」关键字、非回复的新邮件作为询价申请；建任务时解析紧急程度并计算报价截止。

### R-FR-02 必填字段校验与异常回信（阻断）
系统 MUST 校验询价邮件必填字段（备件类型、品牌、PN、数量、规格、成色、收货地址、紧急程度）。凡关键字段缺失或整体无法解析，SHALL 自动回信指出问题，且**不建任务、不进入外部询价**。

### R-FR-03 重复邮件判重
依据邮件 thread_msg_id 判重，避免同一询价重复建任务。

### R-FR-04 外部询价 B（不含收货地址）
向供应商池每家发询价邮件，正文不含收货地址；供应商池为空时不崩溃。

### R-FR-05 报价收集与非标处理
WAITING_QUOTES 按询价线程匹配供应商回复报价；支持纯文本/表格；无法解析的报价保留原文；仅供应商白名单发件人被接受。

### R-FR-06 最低价优选与未选中截止
全部已报价或到截止 → 按单价取最低价为优选项。**未选中供应商在回复报价后即被标记截止**（不再参与后续）。

### R-FR-07 内部审批与工程师双向确认（终态）
- 智能体向工程师询价会话提交审批邮件（抄送审批人，列报价+最低价建议）。
- 审批人回复该会话确认（确认最低价 / 指定供应商 / 全部拒绝）。
- 工程师回复该会话「备件更换完成」→ **内部流结束（R_CLOSED，全流程终态）**。
- 内部流完成后，智能体 MUST 向**外部流供应商会话回复一封结算邮件**，通知「本次采购结束，等待后期结算」。

### R-FR-08 下达订货 E
审批确认后向选中供应商发订货邮件（含收货地址、要求测试报告+快递单号），回复该供应商报价会话。

### R-FR-09 供应商回单号与结算
选中供应商回复快递单号 → 外部流登记发货状态。外部流的**终态**不是回单号，而是：内部流「备件更换完成」触发后，智能体向供应商会话回复**结算邮件**（通知采购结束，等待后期结算）。任务整体 DONE 以内部流完成 + 结算邮件发出为准。

### R-FR-10 配置维护
静态配置（审批人、供应商池、模板、凭据、紧急时长映射）存 `spare_mail_config`，DB 优先。

### NFR-R-01 幂等与单点异常隔离
每 tick 内各 step 独立 try/except，单任务异常不阻塞其它任务推进。

### NFR-R-02 凭据安全
密码类字段读取 API 打码展示；SMTP/IMAP 用 DB 凭据，缺失降级 .env，emp-008 兼容。

## 调度

由后台自动轮询驱动（`main.py _proc_scheduler_loop`），**每 1 分钟**触发一次 `kind=mail-inquiry` tick；不依赖人工 tick 触发业务流程。

## 数据模型

- `spare_mail_task`：双流状态（internal_status/external_status）、thread 映射、suppliers_json、quotes_json、lowest_*、approval_*、urgent/deadline 等
- `spare_mail_config`：审批人/供应商池/模板/凭据/紧急时长映射
