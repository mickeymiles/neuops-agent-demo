# 备件询价申请邮件标准模板（工程师 → 采购智能体）

> 本文是**邮件入口第一封邮件**的唯一标准。后续所有流程都挂在这封邮件上：
> `thread_msg_id`（线程根）、`project_no`、`brand / pn / spec / condition` 全部由它决定，
> 供应商询价函（模板 B）、内部汇总（模板 D）、审批、订货（模板 E）、结算（模板 G）
> 的变量都从这里取值。**第一封写错，整条链路都会错。**

## 二、字段规范（对齐 `_extract_inquiry_fields` 的正则）

来源：`app/routes_procurement_agent.py` 的 `_extract_inquiry_fields()`。

| 字段 | 写法 | 正则约束 | 必填 |
|---|---|---|---|
| 项目编号 | `项目编号：PRJ-TEST-01` | 值**必须以 `PRJ` 开头** | ✅ |
| 项目名称 | `项目名称：xxx` | 2–40 字，不跨行 | ✅ |
| 备件类型 | `备件类型：电源` | 兼容「类型：」，值不含冒号 | ✅ |
| 品牌 | `品牌：Dell` | 1–20 字符，中英文均可 | ✅ |
| PN | `PN：PSU-750` | 兼容「PN料号：」「型号（PN）：」 | ✅ |
| 规格 | `规格：750W 冗余电源` | 兼容「规格参数：」，≤80 字 | ✅ |
| **成色** | `成色：全新` | **必须紧跟枚举值**：`全新` / `原厂翻新` / `拆机二手` | ✅ |
| 数量 | `数量：2` | 兼容「采购数量：」，纯数字 | ✅ |
| 收货地址 | `收货地址：xxx` | 兼容「地址：」，3–80 字 | ✅ |
| 紧急程度 | `紧急程度：2h` | 数字+单位（`min|分钟|h|小时|天|d`） | ✅ |
| 最晚发货时间 | `最晚发货时间：2026-09-02` | **只写日期**，带时间会被截断 | 非必填 |
| 收货人 | `收货人：张启明` | 2–10 字 | 非必填 |
| 联系电话 | `联系电话：13800000000` | 7–20 位数字 | 非必填 |

必填集合（`_MI_LLM_REQUIRED`）：
`project_no, project_name, part_type, brand, pn, spec, condition, count, address, urgent`

缺任一必填字段 → 走 R-FR-02，智能体回信「信息不完整」，**不建任务、不进入询价流程**。

## 三、已知坑（按系统自带模板 A 写会被拒）

系统内 `proc_templates.A` 的正文与解析正则**不一致**，照抄会导致建任务失败：

| 模板 A 的写法 | 解析正则要求 | 后果 |
|---|---|---|
| `成色要求：全新` | `成色\s*[:：]?\s*(全新\|原厂翻新\|拆机二手)` | 「要求」二字卡死匹配 → **判定缺 `condition`** |
| `项目：{project_no} / {project_name}` | `项目编号：` 与 `项目名称：` 分开匹配 | `project_name` 会被解析成项目编号 → **判定缺 `project_name`** |

> 结论：**以本文件为准，不要照抄模板 A 的正文。**
> 模板 A 需要按第二节修正（把「成色要求」改成「成色」、「项目：x / y」拆成两行），
> 已列入重构待办。

## 四、发送要求

- **发件人**：工程师邮箱（本机联调 `biquanzhi1@163.com`），需在智能体的联系人范围内
- **收件人**：采购智能体邮箱（本机 `biquanzhi3@163.com`）
- **主题**：建议带项目编号与型号，便于人工检索；`project_no` / `pn` 也会从主题兜底提取
- **回复机制**：不要用「回复」补字段。智能体只认**新邮件**的正文解析，
  缺字段回信里已明确提示「请勿回复本邮件，请新写一封」

## 五、后续链路（确认第一封没问题后再验）

```
工程师申请(本文模板)
  → 智能体建任务 MI-*，字段落 spare_mail_task
  → 模板 B：发询价函给供应商（标题【询价】{brand} {pn} x {count} — {urgent} 内回复 [{task_no}]）
  → 供应商在 B 线程内回复报价（必须保留 In-Reply-To / References）
  → 比价定标 → 模板 D：发汇总给审批人（标题【询价汇总】{project_no} {brand} {pn} — {n}家报价-最低价优选 [{task_no}]）
  → 审批人在 D 线程内回复 → 模板 E：下达订货
  → 供应商回运单号 → 工程师回执验收 → 模板 G：结算闭环
```

> 线程匹配依赖 `In-Reply-To` / `References`，**任何一步回复都不能丢这两个头**，
> 否则智能体匹配不到任务（表现为 tick 报 `processed: 0`）。
