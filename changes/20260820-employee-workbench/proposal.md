# 提案：数字员工业务工作台

> 变更编号：`20260820-employee-workbench`
> 作者：NeuOps 团队 | 日期：2026-08-20 | 状态：已批准

## 背景与问题

数字员工详情目前只有对话、技能和 MCP 能力视图，无法承载各业务员工不同的指标、任务入口与业务信息。若直接为每个员工编写独立页面，后续无法通过对话稳定调整呈现。

## 目标

1. 在数字员工详情首位提供“工作台”Tab，并按员工配置差异化展示。
2. 以受约束 JSON 契约持久化布局，为后续对话生成配置补丁预留稳定接口。
3. 无自定义配置时按员工业务类型生成可用默认工作台。

## 变更范围

### In Scope

- 员工工作台配置的读取、校验和持久化。
- 指标、列表、快捷动作、说明、受控业务系统五类白名单组件。
- 经营分析员工在工作台内直接嵌入 contract 业务页面。
- 工作台预览、JSON 编辑、保存和恢复默认。

### Out of Scope

- 对话自动提交工作台变更。
- 执行用户提供的脚本、表达式或任意算法代码。
- 连接实时业务指标并计算结果。

## 接口与数据契约

沿用 `PATCH /api/employees/{id}`，新增可选字段 `workbench`：

```json
{
  "workbench": {
    "title": "经营分析工作台",
    "description": "关键经营指标与分析入口",
    "components": [
      {"id": "metrics", "type": "metric", "title": "核心指标", "items": [{"label": "签单毛利率", "value": "--", "trend": "待同步"}]},
      {"id": "actions", "type": "action", "title": "快捷分析", "items": [{"label": "分析经营指标", "prompt": "分析本月经营指标"}]}
    ]
  }
}
```

服务端仅接受 `metric`、`list`、`action`、`note`、`business_app` 五类组件，并限制组件和条目数量。`business_app` 的地址由服务端平台配置提供，员工 JSON 不允许自定义 URL。

## 涉及规格条目

- ADDED `NO-010 FR-1` 数字员工工作台入口
- ADDED `NO-010 FR-2` 配置持久化与约束

## 验收标准

- [ ] 工作台位于数字员工详情 Tab 首位，默认进入工作台。
- [ ] 不同业务类型员工展示不同的默认内容。
- [ ] 合法 JSON 配置可保存并在刷新后恢复，非法配置返回 400。
- [ ] 可恢复该员工的类型默认工作台。

## 风险与兼容性

新增数据库列带默认空值，旧数据自动迁移；现有员工接口字段保持兼容。前端只渲染白名单结构并转义文本，不执行配置中的代码。
