# 提案：投标工作台 SOP 化分步编写流程

> 变更编号：`20260817-bid-writeflow`
> 作者：AI 助手 | 日期：2026-08-17 | 状态：已完成

## 背景与问题

当前投标材料为「一键同步生成」：模板拼装 + RAG 片段，正文大量「待补充材料」占位；
生成不调用大模型、无分步交互、无进度提示；上传的规范书/拆标报告/模板仅落盘文件与
SQLite，未进入知识库，RAG 检索不到项目自有资料；前端生成成功后不刷新项目数据，
导致成果列表显示为空。

## 目标

1. 生成全流程真实调用 DeepSeek 大模型，产出可用的初稿内容
2. 把「需求→假页面→逐章对照编写→组装」固化为带进度条的 6 步 SOP
3. 项目上传的规范书/拆标报告/模板入库，RAG 可检索项目自有资料

## 变更范围

### In Scope

- 上传规范书/模板时保留原文件 + 解析文本写入项目级知识库（bid-project-{pid}）
- 新增需求分析、假页面生成、大纲、逐章生成、组装五类接口，全部走 LLM，失败降级模板
- 前端 6 步步骤条 + 左右对照逐章编辑器（左=规范要求，右=AI 草稿）+ loading 遮罩
- 修复生成成功后成果列表不刷新 bug；拆标卡片加滚动条防页面变形

### Out of Scope

- 知识库页面化配置（仅后端自动建库/写库）
- 投标材料自动定稿（保留人工确认）

## 接口与数据契约

### 新增接口

- `POST /api/bid/projects/{pid}/requirements`   # 需求→结构化 PRD，返回 {prd: {...}}
- `POST /api/bid/projects/{pid}/mockup`         # PRD→假页面 HTML，落盘 outputs/
- `POST /api/bid/projects/{pid}/outline`        # 模板+规范书→章节大纲，返回 {chapters: [...]}
- `POST /api/bid/projects/{pid}/chapter`        # body:{chapter, index, confirm} 逐章生成/重生成
- `POST /api/bid/projects/{pid}/assemble`       # 合并确认章节→最终文档，返回 {doc}

### 修改接口

- `POST /api/bid/projects/{pid}/upload`         # 增加：解析文本入库项目知识库
- `POST /api/bid/projects/{pid}/generate`       # 兼容保留，内部转发分步流程

## 涉及规格条目

- MODIFIED: NO-009 FR-2（上传入库）、FR-4（生成调用大模型）、FR-15（假页面由 LLM 驱动）
- ADDED: NO-009 FR-16（项目资料入库）、FR-17（需求分析）、FR-18（假页面生成）、
         FR-19（大纲与逐章）、FR-20（左右对照确认）、FR-21（流程进度与组装）

## 验收标准

- [x] 上传规范书后项目知识库出现对应文档，RAG 检索能命中项目内容
- [x] 需求分析产出含功能点/页面清单/用户角色的结构化 PRD
- [x] 假页面由 LLM 生成可预览 HTML，含技术参数响应清单
- [x] 逐章模式左右对照：左侧规范要求、右侧 AI 草稿可编辑、每章确认后进入下一章
- [x] 组装后导出 docx/md 为完整文档，含全部确认章节
- [x] 生成成功后成果列表立即显示，无需刷新页面
- [x] 6 步步骤条进度正确，长任务有 loading 遮罩

## 风险与兼容性

- LLM 失败/无 key 时逐章降级规则模板并标记「待补充」，不阻塞流程（TC-2 保持）
- 既有 /generate 接口保持兼容返回 doc 记录
- 项目知识库按 pid 幂等创建，不干扰预置 5 类投标库
