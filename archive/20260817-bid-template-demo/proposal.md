# 变更提案：投标模板上传 + 模板化材料生成 + 技术方案演示网页

- 规格前缀：NO-009（bid-expert）
- 日期：2026-08-17
- 状态：已确认（用户确认方案后落地）

## 背景

1. 投标工作台生成的四类材料 docx 导出已具备排版基线（FR-11/12），但均为**从零渲染**，与客户定稿模板（带封面、页眉页脚、固定章节结构的 docx）格式不统一，交付观感与模板不一致。
2. 投标演示场景需要"高仿真系统界面"效果：当前仅能交付静态文档，缺少可直接浏览器打开、像真系统一样（KPI/图表/表格/告警，数据真实、有图例坐标轴）的演示网页，影响投标现场效果。
3. 演示网页此前已口头确认方案：纯 CSS 模拟界面区块（零依赖、自包含单 HTML），由拆标报告技术参数驱动，数据、图例、坐标轴真实；无交互可接受。

## 目标

- **FR-13 投标模板上传**：工作台上传定稿 docx 模板（单模板覆盖，与"规范书上传 / 拆标解析"三列一行同级），解析章节树，可查看与删除。
- **FR-14 模板化材料生成**：导出 docx 时若存在模板，按章节标题匹配将生成内容插入模板对应章节，整体格式跟随模板；无模板时保持 FR-11/12 基线渲染不变。
- **FR-15 技术方案演示网页**：新增材料类型 `tech_demo`（技术方案演示网页），由拆标报告技术参数驱动生成自包含单 HTML（高保真模拟系统界面），支持预览与下载 html；导出 docx 技术方案时以 Word 表格骨架呈现功能截图区。

## 涉及规格

- `specs/009-bid-expert/spec.md`：ADDED FR-13 / FR-14 / FR-15（见 `specs/009-bid-expert/spec.md` delta）

## 验收标准

1. 上传接口接受 docx 模板并落盘 `uploads/bid/{pid}/template/`（单模板覆盖）；项目详情返回模板名、大小与章节树；支持删除。
2. 生成材料选择 `tech_demo` 时产出 `.html` 成果，可预览（浏览器直接打开）与下载；页面含 KPI 卡、带坐标轴图例的折线/环形图、状态表格、告警列表，数据来自拆标报告。
3. 有模板的项目导出 docx：模板原内容与样式完整保留，生成内容按章节标题匹配插入；无模板项目导出行为与 FR-11/12 完全一致。
4. 导出 docx 技术方案时，"技术方案要点"后插入 Word 表格骨架（功能说明 + 规范引用），作为功能截图区占位。
5. 既有测试全量通过 + 新增 FR-13/14/15 测试通过。

## 不做什么

- 不改动拆标六类章节结构；不改动四类材料 md 生成逻辑（仅新增 tech_demo 与导出扩展点）。
- 不做多模板管理（本期单模板覆盖）。
- 不做 Word 动态目录（TOC 域）——沿用 FR-11 静态目录。
- 演示网页不做动态交互与真实数据联调（仅展示，数据由拆标报告驱动）。
