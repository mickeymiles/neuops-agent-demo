# 变更提案：后台管理"工作成果"菜单增加投标工作台入口

> 变更编号：`20260817-admin-bid-link`
> 作者：售前数字化小组 | 日期：2026-08-17 | 状态：已批准
> 涉及规格：NO-009（MODIFIED，后台管理入口）

## 背景与问题

- NO-009 已交付投标工作台（`/bidding`）与 `static/index.html` 侧边栏入口，但**后台管理门户（`/manage`）的"工作成果"菜单仅列经营业务平台（9006）一个入口**，投标工作台未在后台管理门户中暴露，运维/管理人员从后台无法直达。
- 投标工作台同属本平台（9007），应作为"工作成果"卡片墙中的一个链接入口，与经营业务平台并列。

## 目标

在后台管理（`/manage`）"工作成果"页面（`page-work`）的卡片墙中，新增"投标工作台"卡片，点击新标签页打开 `/bidding`。

## 变更范围

### In Scope

- `static/manage.app.js` → `renderWork()`：`links` 数组新增 `{ title: '投标工作台', desc: '拆标解析 / 材料生成 / 合规自检 / 成果导出', icon: 'folder', url: '/bidding' }`

### Out of Scope

- 不改动投标工作台自身（`/bidding`）功能
- 不改动 `static/index.html` 侧边栏入口
- 不涉及后端 API 变更

## 涉及规格条目

- **MODIFIED**：NO-009 追加 FR（后台管理门户"工作成果"菜单提供投标工作台入口）

## 验收标准

- [ ] `/manage` 登录后"工作成果"页面出现"投标工作台"卡片，点击新标签页打开 `/bidding`
- [ ] 既有"经营业务平台"卡片不受影响
- [ ] `pytest -q` 全量通过（无新增测试必要，纯静态入口；回归验证既有用例）
- [ ] 更新 `specs/TRACEABILITY.md` 并归档本变更目录

## 风险与兼容性

- 纯前端静态改动，`no_cache_static` 中间件已覆盖，无缓存问题。
- 使用相对路径 `/bidding`，同端口同源，不受 9006 外链基础地址影响。
