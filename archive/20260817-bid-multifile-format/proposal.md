# 变更提案：投标多文件分类解析 + 生成格式统一约束

- 规格前缀：NO-009（bid-expert）
- 日期：2026-08-17
- 状态：已确认（用户确认方案后落地）

## 背景

1. 客户招标文件通常包含多个文档：可研文件、格式要求、合同文稿、技术要求、商务要求。当前上传虽支持多文件，但一律合并拆标：
   - 可研中的过时/初步参数会污染正式标书的拆标结果，甚至与正式标书冲突；
   - 格式要求混入技术参数，未用于约束生成文档的排版；
   - 拆标 source 无法溯源到「哪个文件的第几章」，人工核对困难；
   - LLM 分块会跨越文件边界，影响提炼准确性。
2. 生成成果的 docx 导出套用 python-docx 默认模板，无中文字体回退、字号、行距、页边距、页码、封面与目录，观感粗糙。

## 目标

- **FR-10 多文件分类解析**：上传时为每个文件打标签（自动识别 + 手动可改），按类别独立抽取落盘；拆标按类别优先级合并（可研不参与主拆标）；合并文本带【来源文件】头实现 source 溯源。
- **FR-11 投标格式规范（docx 排版基线）**：docx 导出按统一基线渲染——宋体正文小四 12pt、1.5 倍行距、首行缩进、黑体标题（三号/四号/小四）、规范页边距、页脚页码、封面与静态目录。
- **FR-12 格式要求自动提取覆盖**：拆标时从「格式要求」类文件关键词提取排版规范，命中项优先于默认基线。

## 涉及规格

- `specs/009-bid-expert/spec.md`：ADDED FR-10 / FR-11 / FR-12（见 `specs/009-bid-expert/spec.md` delta）

## 验收标准

1. 上传接口接受 `categories`（JSON 映射「文件名→分类」）；未指定时按文件名+内容自动识别；项目详情文件列表返回分类标签。
2. 抽取文本按 `extracted/<category>/` 独立落盘；旧版平铺结构视为 other，可正常拆标。
3. 拆标主文本仅合并 technical/commercial/contract/other；若为空回退全量合并（兼容仅可研场景）。
4. 合并文本按文件分段带【来源文件：文件名】头；LLM 提示 source 须标注「文件名·章节」。
5. docx 导出含中文排版基线 + 封面 + 目录 + 页码；格式要求命中项覆盖默认。
6. 既有测试全量通过 + 新增 FR-10/FR-11/FR-12 测试通过。

## 不做什么

- 不改动拆标六类章节结构（六类契约保持不变）。
- 不做 docx 动态目录（Word TOC 域）——使用静态目录页。
- 不做可研内容智能比对合并（本期仅隔离，不参与主拆标）。
